Please update the blog/post template so every individual blog page automatically outputs its own UNIQUE JSON-LD schema based on that post’s actual content fields.

Goal:
Generate clean, valid, page-specific schema for every blog/project page on the site, using the post data already being used to render the page. Do not hard-code one generic schema block for all posts.

Requirements

1. Add a reusable schema builder for blog posts
Create a utility function such as:
- buildBlogPostingSchema(post)
- buildBreadcrumbSchema(post)
- buildMediaSchema(post) where relevant

2. Use BlogPosting as the primary schema
For each blog page, output a JSON-LD script with @type = "BlogPosting" using the specific post’s fields.

Populate these fields dynamically from the blog data:
- @context: "https://schema.org"
- @type: "BlogPosting"
- @id: canonical URL + "#blogposting"
- mainEntityOfPage: canonical URL
- headline: post title
- description: meta description if available, otherwise home excerpt
- articleSection: "Voiceover Blog" or "Projects" depending on post type if available
- keywords: array made from the search terms field
- image: full absolute URL to the main image
- url: canonical URL
- datePublished: from the post date
- dateModified: from updated date if available, otherwise same as published
- author: Person schema for Guy Harris
- publisher: Organization schema for VoiceoverGuy
- publisher.logo: full absolute URL to site logo
- inLanguage: "en-GB"
- isAccessibleForFree: true

3. Author and publisher details
Use consistent author/publisher values sitewide:
Author:
- @type: "Person"
- name: "Guy Harris"
- url: "https://www.voiceoverguy.co.uk/about"
- image: "https://www.voiceoverguy.co.uk/images/guy-harris-profile.jpg"

Publisher:
- @type: "Organization"
- name: "VoiceoverGuy"
- url: "https://www.voiceoverguy.co.uk/"
- logo:
  - @type: "ImageObject"
  - url: absolute URL to site logo

4. Image handling
If the post has a main image filename, output:
"image": {
  "@type": "ImageObject",
  "url": absolute image URL
}
Make sure image URLs are absolute, not relative.

5. Add BreadcrumbList schema
Output a second JSON-LD block for:
Home > News & Blog > Current Post
Use the actual post title and canonical URL.

6. Add conditional media schema
If a post contains a YouTube video ID:
- output a VideoObject schema
- include:
  - @type: "VideoObject"
  - name: post title
  - description: meta description or excerpt
  - thumbnailUrl: YouTube thumbnail
  - embedUrl
  - uploadDate using full ISO 8601 timestamp with timezone
  - author as Guy Harris
  - publisher as VoiceoverGuy

If a post contains a Vimeo ID:
- output VideoObject using Vimeo embed URL

If a post contains a local MP3:
- output AudioObject schema
- include:
  - @type: "AudioObject"
  - name
  - description
  - contentUrl
  - uploadDate with full ISO 8601 timestamp
  - inLanguage: "en-GB"

Only output media schema when media actually exists.
Do not invent duration if unknown.
Do not add empty fields.

7. Canonical and IDs
Every blog page must use its own absolute canonical URL, based on the post slug.
Example:
https://www.voiceoverguy.co.uk/blog/post-slug
or whatever the site’s final blog URL pattern is

Each schema block should have a unique @id pattern such as:
- canonical + "#blogposting"
- canonical + "#breadcrumb"
- canonical + "#video"
- canonical + "#audio"

8. Date formatting
Convert post dates into valid ISO 8601 format.
Use full timestamps with timezone where possible.
For example:
2025-12-01T09:00:00+00:00

9. Keep schema clean
Do not include:
- aggregateRating
- offers
- review
unless that specific post genuinely contains valid data for those
Avoid invalid or empty properties
Do not duplicate identical schema blocks
Do not output FAQPage unless the page actually has FAQ content rendered on the page

10. Output location
Render the schema in the page <head> or equivalent SEO/head component for each blog post page.

11. Validation
Make sure the schema validates in Google Rich Results Test and Schema.org validator.
No placeholder text, no undefined values, no relative URLs.

12. Fallback logic
If any optional field is missing:
- use meta description fallback to excerpt
- use excerpt fallback to intro text stripped of HTML
- skip media schema if no media exists
- skip image object if no image exists

Implementation note
Please inspect the current post structure and wire the schema directly to the real fields already used by the template, so every blog page gets a genuinely unique structured-data output based on its own content.
